# Архитектура The Elder Deep: Below the Ages

Разбор для R-38 (задача 500, 07.11.2026): что за что отвечает сейчас, где фичи сталкиваются, целевая раскладка модулей и
порядок этапов. Код этим документом не переносится. Номера строк даны по `dev` 4fcbdd3.

Граница «логика / отрисовка» уже соблюдается. В `data.js`, `dungeon.js` и `sim.js` нет ни одного обращения к `window`,

`openChest`…), вызывается только из `SCENE.QA()` (строки 3260+), где QA-состояния строятся прогоном логики.

Главная проблема — размер файлов и то, что их части перемешаны, а не нарушенные границы слоёв.

## 4. Целевая раскладка

### 4.1 Как модули видят друг друга

Модули остаются обычными скриптами с IIFE, файлы лежат плоско в `live/` с префиксом слоя: `pack.py` копирует `live/*.js` как
есть, вложенные папки ему пришлось бы объяснять. ES-модули не подходят: их не возьмёт `require` в `tools/*.cjs`, и они не
работают в собранной игре, открытой из файла.

- **Манифест** `live/modules.js` — один упорядоченный список файлов по слоям. Его читают `index.html` (загрузка и оба списка
  `WATCH` для горячей перезагрузки, сейчас набранные вручную дважды) и загрузчики в Node.
- **Общий объект слоя.** Данные пишут сразу в `DATA` (`Object.assign(root.DATA ||= {}, {...})`). Внутренние части логики
  пишут в `SIMX`, отрисовки — в `SCX`. Публичные `SIM` и `SCENE` собирает последний файл слоя (`sim.js`, `scene.js`) с тем же
  набором имён, что сейчас, поэтому `bot.cjs`, `hud.js` и `tools/` не меняются.
- **Ссылки.** Имена из файлов, загруженных раньше, берутся деструктуризацией в начале файла (`const { cell, solidAt } = SIMX`):
  вызов остаётся голым и таким же быстрым, это важно для горячего шага 120 Гц под ботом. Вызов вперёд, в файл, загруженный
  позже (например, `ev` → `questOn`, `hitEnemy` → `killEnemy` → квесты), идёт через `SIMX.name(...)` в момент вызова. Порядок
  файлов выбирается так, чтобы таких вызовов было мало.
- **Node.** `require('./data.js')`, `require('./dungeon.js')` и `require('./sim.js')` продолжают работать: в Node последний
  файл слоя сначала подтягивает свои части по манифесту. 20+ инструментов из `tools/` не трогаются, кроме тех, что читают
  исходник как текст (`cavedensitycheck.cjs` читает `live/dungeon.js`).

### 4.3 Объект кадра для `SC.render`

Проходы получают один объект кадра `F` (`t`, `S`, `R`, камера, окно, списки огней, `kAt`, `fireTint`, маски, текущий биом),
который `scene.js` строит в начале кадра. Переменные, которые сейчас объявлены внутри `SC.render` и используются
несколькими проходами, переходят в `F`; локальные для одного прохода остаются в нём. Порядок рисования не меняется.
Это единственный этап с правкой обращений к переменным, а не только переносом, поэтому он идёт последним в 503 и по одному
проходу за раз.

Сделано в 503: проходы — `scene_world.js` (земля и Y-полоса одним проходом: земля кладёт в полосу замыкания, которые зовут `halo`
и `flameB` из полосы), `scene_light.js` (свет и композит), `scene_fx.js` (эмиссия); подготовка кадра и пост-обработка остаются в
`scene.js`. Зум и окно вида (`Z`, `VW`, `VH`), `LT` и `LAVA_CLIP` переприсваиваются, поэтому другие файлы читают их через геттеры `SCX`.

### 4.4 Пачки отрисовки и запись позы (задачи 2031–2032)

- `L.stamp(draw, sps)` записывает силуэт рига один раз и повторяет его для каждой копии (обводка, аура, вспышка удара). Запись
  переиспользуется следующим `L.stamp` с той же функцией `draw`, пока между ними не нарисован ни один обычный спрайт, не сменился
  `L.pre` и не начался новый кадр. Контракт: функция `draw` — замыкание одного актёра на один вызов, и код между двумя штампами с
  одной `draw` не меняет состояние рига. Нарушение даст устаревший силуэт без ошибки. `?batch=0` выключает все пачки и
  переиспользование позы — картинка до 2031–2032, эталон для `samecheck --query batch=0`; `?stamp1=0` — только копии и позу.
- Копии одной части рига идут одним инстансинг-вызовом `G.drawN` (программа `spriten`, сдвиги `u_off`); прямоугольники `L.solid`
  без поворота копятся в `G.solid` и уходят пачкой `G.flush` (программа `solidn`). Пачку отправляет любой другой вызов, смена
  смешивания, цели или обрезки и конец `SCENE.render`. Во время записи `L.stamp` оба пути запрещены (бросают ошибку): `L.solid`
  тогда рисует обычным `G.draw`.
- У пакетных программ свои вершинные шейдеры: массивы в общем шейдере на ANGLE/Vulkan удорожают каждый вызов всех программ.
- Инструменты, которые перехватывают `G.draw`, видят копии через `G.drawN`, а прямоугольники — через `G.solid`/`G.onFlush`.
