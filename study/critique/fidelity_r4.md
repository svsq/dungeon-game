## 4. Главные исправления по величине видимого разрыва

### 1. Свет без цвета: камень у огня серый, кадр в полтора раза бледнее

- **ЧТО:**
  - `live/scene.js`, шейдер `LIT`, строка после `l = 3.2 * tanh(l / 3.2);`;
  - стена у факелов: кроп 1198–1278 × 422–512.
- **ПОЧЕМУ:**
  - C p90 кадра 29,7 / 58,9;
  - насыщенного тёплого 3,0 / 15,1%;
  - стена у факела C p50 8–21 / 33–35 при равной яркости;
  - боевая комната C p90 40,9 / 49,4.
- **Что не помогает.** Свет факела `[1, 0.5, 0.16]` вместо `[1, 0.62, 0.26]` (`var_torch.png`) даёт всего 3,1 → 3,8%: серый камень гасит цвет света.
- **КАК:** насыщенность света перед умножением на альбедо, проверено (`var_lightsat.png`):
  ```glsl
  l = 3.2 * tanh(l / 3.2);
  l = max(vec3(0.0), mix(vec3(dot(l, vec3(0.3, 0.5, 0.2))), l, 1.6));
  ```
  Итог: C p90 кадра 39,1, C > 40 9,5%, тёплого 5,7%. Боевая комната: C p90 **49,5 / 49,4**, C > 40 17,2 / 16,5%. Синее и зелёное — 3,0 / 4,0%.
- **Приёмка:**
  - боевая комната C p90 45–55;
  - стена в 2 клетках от факела C p50 ≥ 25;
  - кадр C p90 ≥ 38.

### 2. Кладка листом вместо тонкой кромки над пустотой

- **ЧТО:** `live/scene.js`:
  - `voidTex()`: `Math.max(SS(1.8, 3.2, d[i]), …)`;
  - `rockDist()`: `open = cells !== 0`;
  - `LIT`: строка `vd = smoothstep(...)` — рваный край;
  - `LIT`: маска верха.
- **ПОЧЕМУ:**
  - крупнейшее пятно кладки 234 / 17,7 тыс. px;
  - толщина p90 28 / 15,6;
  - поле кладки p90 13 / 57–63;
  - край пустоты — круглые мягкие кляксы. В концепте край ступенчатый по блокам.
- **КАК:**
  - `SS(1.8, 3.2)` → `SS(1.1, 2.0)`. При `SS(0.9, 1.7)` проверено: кладка 11,2%, толщина p90 15,3 / 15,6, пятно 77 тыс., пустота 41% — перелёт; середина даст ~30% / ~15%.
  - В `rockDist` клетки нераскрытых секретных комнат считать скалой, пока тайник не найден. Сейчас нераскрытый тайник выдаёт себя прямоугольником кладки 8×11 клеток.
  - Шум края квантовать по блоку верха, ~14 view px при периоде 96 на 7 блоков: `vec2 wb = floor(wp / 14.0) * 14.0` в обоих `fbm` и `smoothstep(0.45, 0.55, …)` вместо `0.2, 0.8`. Край пойдёт блоками, как в концепте.
  - Фаски на свет: светлые тексели верха (фаска) не гасить до ambient. В `LIT` множитель маски верха `* (1.0 - smoothstep(0.16, 0.28, max(c.r, max(c.g, c.b))))`. Фаски у огня загорятся, тело блока останется тёмным.
- **Приёмка:**
  - кладка 13–19%;
  - толщина p90 13–18 px концепта;
  - крупнейшее пятно ≤ 40 тыс.;
  - пустота 27–35%;
  - кладка в 3 клетках от факела p90 ≥ 35.

### 3. Враги в пятне жаровни светлые, а не «тёмное тело с кромкой»

- **ЧТО:**
  - `live/scene.js` `drawEnemy`, строки 534–535 (`grade [sat, 0.85, 0, 1.05]`, `rim [0.55, …, 0.012]`, `RIM.col` общий);
  - `data.js` `ENEMIES`.
- **ПОЧЕМУ:**
  - демон p50 29,4 / 9,7;
  - паук 30,6 / 8,5, тёплых 64%, холодных 0 / 29%;
  - гоблин C p90 31 / 51;
  - чёрного в боксах 0,5–19% против 17–37%.
- **КАК:**

## 6. Нарушенные правила

- **Style bible, «Line».** Тёмный контур в 1 пиксель вокруг персонажей: у нас кромка L < 8 только у 4–17% px, свет красит чернила.
- **Style bible, «Palette».** Акценты тлеющего оранжевого — у нас насыщенного тёплого в 5 раз меньше. Обратное «muted» тоже нарушено: красного на герое 40%.
- **`art.md`: спрайт читается в размере показа.** У героя нет лица, у гоблина перепадов вдвое меньше, чем у концепта.
- **`gamefeel.md`: интерфейс не закрывает актёров.** Паук закрыт на 22,5%. Обратная связь — над целью, а цифры лежат на теле.

## 7. Мелочи

- Миникарта: карта 190×150 против ~200×312 при k = 1,25. Маркеры — самоцветы, а не иконки (босс у концепта — череп). Вид тот же, площадь меньше.

- Внешняя скала (L 2,9, бурые прожилки) мягкая и мутная. У концепта пустота — чистый чёрный 0–2. По доле не мешает, на крупном плане читается как дым.
- Контактная тень героя L 8,1 / 13,9 — темнее концепта; после фикса 1 проверить ещё раз.
