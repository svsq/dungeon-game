**Главное, что видно на скриншоте:** левая дверь (x 364–489, y 925–1165) — это НЕ закрытая дверь, это **открытое** состояние
`door_side_open` (полотно анфас + блоки косяка). Игрок принял её за закрытую — это и есть самый сильный дефект. Правая (x 1326–1394,

## Топ-исправления по влиянию

### 1. Открытая боковая дверь читается как закрытая
- **ЧТО:** скриншот x 364–489 y 925–1165; QA `door_l_open` (кроп q_door_l_open). `scene.js`, ветка `if (side)`, `p > 0`:
  `L.sprite('door_side_open', left(wo), top, …)` с тем же `top`, что и у закрытой.
- **ПОЧЕМУ:** полотно анфас 42×78 view px, низ полотна (src-строка 611 из 818) стоит на `bot − 176·k = sy(d.y)+32` — оно перекрывает
  верхнюю половину пола коридора (32 из 64 px) и всю его ширину от косяка, а на скриншоте при зуме и фоге — фактически весь
  проход. Анфас-плоскость = «дверь, обращённая к камере» = закрыто. Яркость полотна та же, что у закрытого (не уходит в тень).
- **ИЗМЕНЕНИЕ (код, без новой графики):** открытая створка прижата к фасаду ВЕРХНЕЙ стены коридора, её ступня — на верхней линии
  пола, пол коридора остаётся свободным:
  ```js
  const footOpen = 611;               // нижняя строка дерева в door_side_open
  const topO = sy(d.y) + 2 - footOpen * k;          // низ полотна = верх пола коридора
  Y.push([d.y - TILE, () => L.sprite('door_side_open', left(wo), topO, { w: wo, h: footOpen * k, flip,
    src: [0, 0, 1, footOpen / ASSETS.door_side_open.h], u: { alpha: p, grade: [0.75, 0.9, 0, 1] } })]);
  ```
  (обрезать нижний косяк из этого спрайта через `src`, нижний косяк остаётся отдельным `door_side_jamb`). Плюс тёмная полоса-тень
  2 px под ступнёй. Добавить QA-состояние `door_l_open_clear`: проверка, что ≥90% клеток пола коридора за дверью не перекрыты спрайтом.

### 2. Открытая нижняя дверь — «шест»
- **ЧТО:** скриншот x 879–905 y 1165–1498; QA `door_d_open` x≈915–925 y 520–660 (кроп q_dopen). `scene.js`:
  `th = (Math.PI/2 − 0.16)·p`, `A = [cos th, sin th, 0, 1, …]`.
- **ПОЧЕМУ:** вектор ширины = (62·0.16, 62·0.99) = (10, 61) view px → полоса ~8 px шириной и ~141 px длиной; планки и полосы железа
  сжаты в 16% ширины. Яркость полосы 38.7 против пола рядом 45.1 (Δ6/255) — силуэт без контраста, ни кольца, ни полос не видно.
  Аффинный сдвиг ещё и наклоняет низ полосы: ни одна деталь не держит форму.
- **ИЗМЕНЕНИЕ:** не сжимать анфас-полотно. Створка, распахнутая на 90°, стоит в плоскости С–Ю — это ровно тот ракурс, который уже
  нарисован в закрытой `door_side` (полотно «сверху-слева»). Нужен спрайт `door_side_leaf` (полотно из `door_side` без косяков;
  вырезать скриптом `tools/*.py` по маске дерева, либо перегенерировать — см. промпт ниже). Тогда:
  - открытая нижняя дверь: `door_side_leaf` (зеркало при петле слева), петля у левого края проёма, ступня на `sy(d.y)+TILE+…`, ключ
    сортировки по нижней ступне;
  - открытая верхняя дверь: то же полотно за аркой (сейчас оно уходит за фасад почти целиком — ок, но анимация поворота
    квада тоже вырождается в полосу на средних `p`; держать квад только до p≈0.5, затем кроссфейд в `door_side_leaf`);
  - открытая боковая дверь (п.1): анфас-полотно = существующий `door_leaf` — один и тот же дизайн во всех состояниях.
  Итого набор: 2 ракурса полотна (анфас `door_leaf` и ребро `door_side_leaf`), а не 4 разных рисунка.

### 3. Закрытая боковая створка перекрывает героя рядом с ней
- **ЧТО:** QA `door_key_r` x 990–1000 y 520–640, `door_bar_l` (кропы q_key, q_bar): полотно рисуется поверх ног и руки героя,
  стоящего в комнате у двери. `scene.js`: `Y.push([d.y + 2 * TILE - 6, …'door_side'…])`.
- **ПОЧЕМУ:** ключ = низ проёма (d.y+58), а герой у двери имеет y от d.y до d.y+58 → дверь всегда «ближе». Створка стоит вдоль
  линии С–Ю, её ступня диагональна по y — один ключ на весь спрайт тут неверен (polish §7).
- **ИЗМЕНЕНИЕ:** рисовать `door_side` 4 горизонтальными полосами `src: [0, r0/H, 1, r1/H]`, ключ каждой —
  `d.y + clamp(top + r1·k − sy(d.y), 0, 2·TILE − 6)` (мировая y ступни этой строки). Верхние полосы уходят за героя, нижние остаются
  перед ним. Замок/засов — с ключом своей полосы. QA-состояние: герой у боковой двери на y = d.y+20.

### 4. Косяки — светлые 3/4-кубы на стене, нарисованной плоскими верхушками
- **ЧТО:** скриншот x 494–577 y 884–1248 (левая) и x 1269–1331 (правая); `door_side`, `door_side_jamb`.
- **ПОЧЕМУ:** средняя яркость блока косяка 67 против верха боковой стены рядом 20 (×3.3), бежево-моховой против холодного
  сланца стены; у блоков нарисованы передние грани, у стены их нет. Читаются как два валуна/ящика, а не как торец стены.
  Плюс зеркалирование для левой стены переносит освещённую грань на правую сторону (свет справа-сверху).
- **ИЗМЕНЕНИЕ (код):** косяки не рисовать из картинки — дорисовать торцы самой стены текстурой `B.top` (как это уже делает
  секретная стена, `scene.js:625`): по одной клетке 32×20 над и под проёмом,
  `L.sprite(B.top, x, y, { w: 32, h: 20, src: [u0, v0, u0 + 32/160, v0 + 20/160], u: { grade: [0.9,1.0,0,1.1], tint: B.tint } })`
  + тёмный край 3 px (`L.solid(..., [0.02,0.015,0.02], …, 0.75)`) со стороны проёма. Из `door_side`/`door_side_jamb` маской убрать
  камни (останется полотно = `door_side_leaf` из п.2). Цвет, тексель и перспектива стены совпадут автоматически.

### 5. Размер створок не един
- **ЧТО:** `DSIDE.k = 0.15` против `DOOR.h = 80`.
- **ПОЧЕМУ:** закрытая боковая створка — ~696 src px дерева × 0.15 = **105 view px**; открытая боковая — 520 × 0.15 = **78**;
  верхняя/нижняя — **80**; герой 84. Одна и та же дверь «усыхает» на 26% при открытии; весь спрайт `door_side` высотой 123 px
  на проём 64 px торчит на 54 px вверх по фасаду коридора.
- **ИЗМЕНЕНИЕ:** масштаб полотна по высоте полотна, не по холсту: `k_side = 80 / 696 ≈ 0.115` для закрытой (и для
  `door_side_leaf`), анкер — ступня полотна на `sy(d.y)+2·TILE−6`; открытая анфас = `door_leaf` 62×80 (п.1/п.2).

### 6. Засов (рычажный замок) — программерский прямоугольник
- **ЧТО:** `door_bar_l` (кроп q_bar): серая полоса `L.solid` 30×7 + блик 2 px, наклон 0.55 рад, выходит за узкое полотно (~22 px
  видимой ширины) на 8 px.
- **ПОЧЕМУ:** polish §9/§11 — плоский прямоугольник без аутлайна и текстуры рядом с нарисованным железом полотна.
- **ИЗМЕНЕНИЕ:** отдельный спрайт `door_bar` (железный брус с двумя скобами) в том же листе, что `padlock` (промпт ниже); для
  боковой — та же картинка со сдвигом/сдвиговой матрицей по наклону полос (`DSIDE.band`), длина = видимая ширина полотна.

## Нарушенные правила
- critics.md §0 п.7 (сортировка/перекрытие: створка над героем; открытая створка поперёк прохода).
- §0 п.10 (состояния читаются с первого взгляда: открыто читается как закрыто, открытая нижняя — не дверь).
- §0 п.2 (тексель: квад с осью ширины 16% — те же «миксели», что и масштаб в другую кратность).
- §0 п.3 / art.md §189 (свет — униформы движка, отзеркаленный рисунок с запечённым светом слева-сверху даёт свет справа).
- §0 п.9/11 (засов — `L.solid`-прямоугольник).
- art.md таблица «Scale and texel density vary»: размер створки задан масштабом холста (0.15), а не высотой класса.
- Перспектива: боковые/нижние стены без фасада, а косяки — кубы с фасадом (смешение ракурсов в одной стене).

## Мелочи
- Закрытая нижняя дверь (`door_r`, x 680–760 y 700–830): полотно анфас без рамки и без тени по низу, верх полотна на 16 px заходит
  на пол комнаты — читается как «прислонённая доска». Дать ей тёмную полосу-проём 4 px по краям и тень `L.shadow` у ступни.
- Замок 24 px на узком наклонном полотне почти теряется (на `door_key_r` закрыт героем); на боковой двери поднять замок на
  ~10 px выше центра полотна или увеличить до 28 px; запертая дверь могла бы иметь цепь поперёк — одно состояние на взгляд.
- Анимация распахивания верхней двери (`door_u_swing`): на p≈0.5–0.9 квад тоже вырождается в полосу — см. п.2 (кроссфейд).
- Открытая боковая и закрытая — один и тот же `top`/`left` с разными холстами (498 vs 300 px): позиция петли «прыгает» на
  кроссфейде (`alpha: p`/`closed`), стоит выровнять по `DSIDE.jx` у обоих холстов отдельно.
- Верхняя дверь в арке (`door_u`) — образец: тексель, аутлайн и посадка в фасаде верные; её не трогать.
