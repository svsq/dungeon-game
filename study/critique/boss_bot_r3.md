## Seed53: ложный тупик бота у прилавка после победы

Исходный `/tmp/game-expert53.bin` содержит живого героя `(928.0049405396196,1318.1373316491045)`, HP690, `arena.active=0`, главного босса уже нет. Цель `fight[17,48]` относится к оставшимся обычным монстрам.

Клетка героя `[29,41]` входит в `m.block`, хотя физически свободная верхняя кромка прилавка проходит через неё. Для flow к `[17,48]` текущая клетка имеет -1; справа20, снизу18, слева/сверху -1. В `walk` условие `inProp` запрещало оба положительных соседа, потому что они направлены к центру текущей клетки. При `best=null` бот переходил на прямую диагональ к цели, то есть left+down, и упирался в прилавок.

Три физических блока прилавка: `(880,1334)`, `(912,1334)`, `(944,1334)`. Локальные 90 SIM.step без бота доказывают доступность обхода:

| Ввод | Конечная позиция |
|---|---|
| Только left | `(770.1394,1320.7461)` — вышел |
| Только right | `(1058.8416,1320.7500)` — вышел |
| Только up | `(928.0517,1255.3246)` — вышел |
| Только down | `(928.7762,1317.8436)` — остался |

Исправленный `walk` при `inProp && !best` задаёт кардинальное направление через существующие `backT/backX/backY` на0.7с. Направление не меняется посреди клеток и не создаёт пингпонга. Выбор проверяет реальную floor-cell, позволяя пройти по свободной кромке через консервативно заблокированные клетки. Это сохраняет продолжение исследования этажа после босса; давление этажа не срезается принудительным уходом к выходу.

Прочитан `/tmp/game-expert53-fixed.json`: **win**, этаж8, все8 строк этажей; встреча с боссом завершена `done:1,died:0`. Целевой повтор ведущего подтвердил исправление исходного зависания.

## Seed70: соседний монстр будил босса до запирания арены

Диагностический повтор с checkpoint6 дал win, но независимый повтор исходного checkpoint8 **воспроизвёл stuck**. Поэтому успешный поздний альтернативный путь не использован как доказательство отсутствия дефекта.

В stuck `/tmp/review-expert70.bin`: герой `(691.9951,854.6882)` внутри арены, босс `(730.7491,881.1011)` с полными HP7200 снаружи, на закрытой клетке5 `[22,27]`. Комната `x4,y14,w18,h14`, правый крайx704. Flow к центру босса отсутствует.

### Первичный переход

Сохранён `frames/study/expert70_aggro_before.bin` с `{S,inp}` непосредственно перед пробуждением; trace `/tmp/review-expert70-aggro.json`.

До тика `S.t=802.4916666661012`:

- boss1092: idle, `(427.8048,597.8456)`, room0;
- ghost1094: idle, `(560,822)`, room0;
- герой `(730.1881,785.7413)` ещё снаружи, `R.arena=null`.

Старый следующий тик выдавал `alert id1094` и переводил главного босса в chase. Причина — `aggroRoom` будил всех idle в той же комнате/рядом, не проверяя защиту ожидающего босса. Прямой агр в stepMonsters такую защиту уже имел.

Ранний босс начал charge и прошёл через ещё открытую дверь. Первый выход из комнаты: t808.983333332762 →808.9916666660953, позиция `(703.6067,859.3192)` → `(706.6226,862.4309)`, `arena=null` до/после. Арена закрылась лишь в810.975, оставив босса снаружи. Это не повторный пробой исправленного swept move. Fixture выхода: `frames/study/expert70_boss_before.bin`, trace `/tmp/review-expert70-escape.json`.

### Проверка исправления

В свежем процессе повторно выполнен один тик из **того же fixture первичного агра** после изменения `aggroRoom`: ghost переходит в chase, boss остаётся idle, арена всё ещё null. Условие допускает босса после появления R.arena и сохраняет старое поведение карт без bossType.

Просмотрена новая selfCheck-регрессия: до входа героя вызывается соседний агр в комнате босса и проверяется его idle для каждого из четырёх типов. Ведущий подтвердил `tune.cjs: selfCheck ok` после обоих исправлений.

Прочитан `/tmp/game-expert70-fixed.json`: **win**, этаж8, все8 строк; boss8 `done:1,died:0`, длительность26.6с. Исходный checkpoint скопирован в `/tmp/review-expert70_f8.bin` перед диагностикой, поэтому параллельные измерения его не меняли.

## Правила и оставшиеся замечания

Причины обоих зависаний установлены по состояниям и отдельным переходам. Добавление guard в общий путь агра закрывает класс преждевременного старта босса, а фикс бота использует уже сериализуемое состояние обхода. Новых блокеров snapshot/RNG/метрик не выявлено.

Текущие полные кампании необходимо закончить на итоговом коде: исправленный агр может менять ранние этажи с промежуточными боссами. Результаты replay с поздних этажей используются только для целевой проверки и предварительной калибровки. Непосредственная приёмка баланса остаётся отдельной проверкой ведущего.
