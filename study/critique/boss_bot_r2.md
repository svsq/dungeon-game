### Регрессии валидатора результатов

Все команды используют `--from-json`, не запускают ботов.

| Набор | Ожидание | Получено |
|---|---|---|
| `/tmp/review-count-stuck.json`: seed1 stuck + seed2 win | Отклонить | exit2, `incomplete result (stuck)` |
| `/tmp/review-count-duplicates.json`: seed1 dead + seed1 win, seed2 отсутствует | Отклонить | exit2, duplicate1 + missing2 |
| `/tmp/review-missing-run.json`: seeds1–2, по одному run, запрошено2 | Отклонить | exit2, `1 runs, expected 2` и `run 2: incomplete result (missing)` для обоих seed |
| `/tmp/review-valid-runs.json`: seeds1–2, по два законченных run | Принять | exit0, `every band met` |

Шаблон команды:

```sh
node tools/difficulty.cjs --from-json FILE --seeds 1-2 --profiles expert --diff hard --runs 2 --check
```

Для первых двух наборов использовался `--runs 1`. Новый проход полноты охватывает все запрошенные профили, даже если для них нет BANDS. Проверяются длина каждой строки, seed каждого run и законченный `how` (`win`/`dead`), поэтому timeout также отклоняется этим же условием.

## Проверка исправления resume

В ходе раунда обнаружено: ранее callback дописывал повтор рядом с старой неполной строкой, и новый валидатор закономерно отклонял итог. Исправление ведущего проверено повторно до завершения этого отчёта.

Загрузка resume теперь сохраняет только строки с точным количеством runs, согласованными seed и законченными win/dead. Успешный callback заменяет результат данного seed.

`/tmp/review-resume.cjs` теперь даёт exit0 вместо прежнего duplicate/incomplete. Расширенный `/tmp/review-resume-variants.cjs` запускает неизменённый difficulty.cjs в VM с подменой execFile готовым ответом: настоящие боты не запускаются.

| Сохранённая строка | Вызов повторного расчёта | Финальный check |
|---|---:|---|
| Один run при запрошенных двух | 1 | exit0 |
| Второй run завершён timeout | 1 | exit0 |
| Во втором run другой seed | 1 | exit0 |
| Два корректных законченных run | 0 | exit0 |

Повторы получают один полный массив результата; старые неполные строки больше не участвуют в итоговых метриках.

## Правила и мелкие замечания

Принцип ref2game «закрыть класс дефекта, а не единичный случай» выполнен для перемещения: общий `move` исправлен и дополнен четырёхсторонней регрессией. Проверки целостности измерений теперь отделены от диапазонов баланса.

Ограничение из раунда1 о совместимости старых префиксов и текущих параметров остаётся: replay с этажаN применим, когда изменённые данные не влияют на предыдущие этажи. Новых блокеров в snapshot/RNG не найдено. Поскольку общий move изменился, текущие результаты replay с позднего этажа пригодны для предварительной калибровки; итоговая приёмка баланса требует полного прогона с первого этажа. Ведущий это подтвердил.
